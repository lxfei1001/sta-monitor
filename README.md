# 亚马逊好仓库监控自动化 · 设计方案

> 版本：v1.1 ｜ 日期：2026-09-20 ｜ 状态：设计已定稿，待 POC 验证

## 1. 需求

做亚马逊电商，需要监控领星 ERP 创建 STA 后亚马逊分配到的入库仓库（物流中心编码）。
若本次分配到的仓库中，**好仓库（白名单 30 个）去重后 ≥ 3 个**，则在日志中醒目标记提醒（暂不外发推送）。

## 2. 已定决策（2026-09-17 与用户确认）

| 决策点 | 结论 |
|---|---|
| STA 处理方式 | **先试「暂存」**——验证暂存是否同样返回入库配置；可行则全程不产生正式货件，零风险。不可行再降级为「创建后立即取消」（需注意频繁取消货件影响账户入库限额） |
| 触发方式 | **丢 Excel 触发**——店铺 Excel（文件名 = 店铺，如 `STORE-US.xlsx` → 店铺「STORE-US美国」）放入监控目录即执行 |
| 判定口径 | **全部仓库去重后 ≥3**——把本次所有货件方案出现的物流中心编码合并去重，命中白名单 ≥3 个即提醒 |
| 通知方式 | **暂不接钉钉，仅本地日志**（2026-09-20 确认）——命中达标时写入 `logs/alerts.log` 醒目标记并在运行输出中播报；后续想加钉钉/其他渠道随时可启用（设计已预留） |
| 重试策略 | **未达标 10 分钟后重试**——每次尝试间隔 10 分钟，默认最多重试 6 次（即约 1 小时窗口，可在配置里改），全部未达标则放弃本轮并记录 |
| 全程留痕 | **每次尝试全量记录**——无论是否达标，都把亚马逊推荐的全部仓库（含各方案明细）落盘，方便后续核查 |

## 3. 总体流程

```
店铺 Excel ──放──> sta-monitor/input/
                        │ (文件名 = 店铺)
                        ▼
        浏览器自动化：登录领星 ERP
        打开 erp.lingxing.com/erp/msupply/AddSendToAmazon
        选择店铺 → 导入商品(Excel) → 点「暂存」
                        │
                        ▼
        抓取「入库配置选项」全部货件的物流中心编码
        （含方案明细：件数、仓库列表、运费）
                        │
                        ▼
        与 config/warehouse_whitelist.json 比对（去重）
        ▲
        │ 每次尝试全量落盘 logs/（仓库明细+截图）
                        │
              ┌─────────┴─────────┐
           命中 ≥3               未达标
              ▼                     ▼
        ALERT 写入日志        等待 10 分钟 → 重新暂存重试
        logs/alerts.log       （默认最多 6 次，用尽则记录放弃）
        (店铺/命中仓库/方案明细)
```

### 3.1 重试与留痕细则

- **重试**：每次尝试间隔 **10 分钟**，默认最多 **6 次**（覆盖约 1 小时窗口）。次数、间隔可在 `config/warehouse_whitelist.json` 的 `retry` 字段调整。若第 6 次仍未达标，本轮结束并在日志标记 `gave_up`。
- **留痕**：每次尝试（无论是否达标）都写入一条 `logs/attempts.jsonl` 记录 + 一张结果页截图：
  - 时间戳、店铺、第几次尝试
  - 本次推荐的**全部**物流中心编码（去重 + 按方案分组的明细：件数 / 仓库列表 / 运费 / 有效期）
  - 命中好仓列表、命中数、判定结果（`alerted` / `retry` / `gave_up`）
  - 结果页截图路径（`logs/screenshots/<店铺>_<时间>_第N次.png`）
- 命中达标即写入 `logs/alerts.log`（ALERT 级）并停止重试（同一店铺同一轮只记一次）。

## 5. 判定逻辑（伪代码）

```
for attempt in 1..retry.max_attempts:           # 默认最多 6 次
    codes = 抓取本次创建所有货件方案的「物流中心编码」
    codes = dedupe(codes)                    # 例如 [MCI4, VGT2, FWA4, AVP1, IAH3, HEA2, BNA6]
    hits = codes ∩ whitelist.warehouses      # 命中好仓，例如 [VGT2]
    记录到 logs/attempts.jsonl               # 全量留痕：全部仓库 + 方案明细 + 截图（无论是否达标）
    if len(hits) >= whitelist.threshold:     # 默认 3
        ALERT 日志(logs/alerts.log：店铺、命中仓库列表、各方案明细、运费、截图)
        break                                # 达标即停，不重复标记
    elif attempt < retry.max_attempts:
        等待 retry.interval_minutes 分钟      # 默认 10 分钟
else:
    日志标记 gave_up，本轮结束
```

命中提醒日志格式（`logs/alerts.log`，同时在运行输出中打印）：

> [ALERT] 好仓库提醒：STORE-US 命中 3 个好仓
> 命中：VGT2、ONT8、LGB8
> 方案1（5件, $0.00）：MCI4 / VGT2 / FWA4 / AVP1 / IAH3
> 方案2（1件, $116.80）：HEA2
> 方案3（1件, $160.60）：BNA6
> 时间：2026-09-17 20:00

## 6. 风险与注意事项

1. **暂存验证是 POC 第一优先级**：若「暂存」不出入库配置，再改用「创建后立即取消」，并限制探测频率（建议同一店铺一天最多探测 1~2 次），避免频繁取消货件影响亚马逊入库限额。**重试策略与暂存强绑定**——10 分钟×6 次的重试只有在「暂存」路径下才安全；若降级为「创建后取消」，重试次数应下调到 2 次以内。
2. **登录态**：领星需要账号登录。POC 时在浏览器里手动登录一次，自动化复用已登录会话；若会话过期，流程会暂停并提醒你重新登录。
3. **账号风控**：领星 Web 高频自动化可能触发风控，执行动作之间保持人速节奏（2~5 秒间隔），不并发。
4. **入库配置有有效期**（截图中显示「有效期 2026-09-20」），提醒消息里会带上配置有效期，过期前的分配结果仅作参考。
5. **领星 MCP 连接器**（lingxing-mcp，未连接）官方说明是查询店铺/库存/Listing/广告数据，不确定覆盖「创建 STA / 入库配置」，暂不作为主路径；连接后可在 POC 时顺手验证，若能拿到入库配置数据则优先走 API（比浏览器稳定得多）。
